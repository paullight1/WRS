# Standalone WRS Admin Console Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move WRS operator UI into an independently buildable `admin/` workspace, sharing current identity and APIs, with the reference-inspired responsive dashboard in persistent light and dark themes.

**Architecture:** Keep the customer app, API routes, auth provider, session rules, and authorization at repository root. Add an npm workspace under `admin/` for the admin entry point and interface, importing only the existing shared auth/domain/API client modules from root. The admin frontend targets the existing API origin with credentialed fetch; root API handlers allow only configured WRS web origins for CORS and CSRF.

**Tech Stack:** React 18, Vite, React Router, Mantine 8, npm workspaces, existing WRS auth/API, Vercel.

**Spec:** `Docs/superpowers/specs/2026-10-05-standalone-admin-design.md`

## Global Constraints

- The WRS API and authorization remain at repository root; do not duplicate or relocate server mutations.
- The standalone admin app is the only app built from `admin/`; the customer app continues building from repository root.
- Use an admin-only API origin setting; empty origin preserves existing relative same-origin requests.
- Keep Secure, HttpOnly, host-only, SameSite=Lax session cookies; do not widen their Domain.
- Credentialed CORS and CSRF checks accept only explicitly configured WRS origins; wildcard origins are forbidden.
- Admin summary data and actions remain permission-checked on the server; MFA step-up and audit requirements remain intact.
- Default the admin theme to light; persist its choice separately from customer preferences.
- No DNS changes, Vercel project creation, domain assignment, or production deployment.

## Review Focus

- **Admin API origin missing in production:** build fails with an actionable configuration error instead of sending credentials to the static admin host; test in Task 1.
- **Untrusted web origin on credentialed request:** no CORS permission is returned and mutation remains rejected; test in Task 3.
- **Operator has a partial role or no role:** only server-authorized scopes/data render; forbidden scopes/actions stay denied; test in Task 4.
- **Theme storage is malformed or unavailable:** app falls back to light and remains usable; test in Task 5.
- **Deep link or refresh on an admin scope:** standalone app returns the SPA shell and preserves the requested scope; test in Task 6.
